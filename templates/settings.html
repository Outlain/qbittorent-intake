Where do I find my token?

Run this on the Docker VM:

docker exec torrent-intake cat /app/data/admin-token

Use HTTPS or a trusted localhost tunnel. The token is kept only in this page's memory, not browser storage. A fresh installation has its own token, including after restore.

Pausing stops Intake's management, scan and post-promotion workers, not qBittorrent downloads or moves already requested. A running copy or script becomes interrupted and needs review before an explicit retry. Wait for “drained” before saving or backing up.

    {% elif group.id == 'storage' %}
    Optional copy after successful promotion

    Intake first scans the torrent and verifies that its move to the final location is complete. After the buffer delay, it checks again, then copies only that torrent's file or folder using a matching rule. Originals remain in place. This is a one-time copy, not a folder synchronization or deletion service.

    In Portainer, mount the copy storage into Intake under /copy-target. Create each rule's destination folder and its .intake-copy-mount marker on the intended mounted filesystem. Then unlock advanced fields, add source-to-destination rules below, enable copying, review/save, restart, and verify/resume. No custom script or TI_POST_PROMOTION_SCRIPT variable is needed.

    For example, /downloads/Media → /copy-target/Media copies a promoted torrent at /downloads/Media/Action/Payload to /copy-target/Media/Action/Payload. Relative folders are preserved without an extra job folder. The most specific enabled matching source wins. Unmatched torrents are not copied; the legacy global destination is not a fallback.

    Choose built-in copying or a custom script, not both. Enabling one switches off the other in your draft when both fields are editable. Portainer overrides must be removed there before editing here. Rules apply to newly promoted jobs, not historical completed jobs; already queued copies retain their pinned rule.

    Existing destination content is protected from overwrite. Copy status is separate from scan and promotion status. If a copy fails or is interrupted by a pause/restart, inspect its destination before explicitly retrying from the job details; promotion itself remains successful.

    Directory copies may be visible before they finish. Wait for the job's copy status to succeed before using the destination. Private copy records are kept under the destination root's .intake-copy-state, outside the copied torrent.

    {% elif group.id == 'deployment' %}
    Docker deployment is separate from application settings.

    Host mount paths, ports, UID/GID, image tags and resource limits must be changed in Portainer. This app sees container paths, not the host mapping. Keep /app/data on local SSD storage.

    The separate ClamD container controls CLAMD_MAX_SCAN_SIZE_MIB, its own definition-age limit and socket configuration. This UI cannot read or change those sidecar values. Application stream limits do not override them.

    Retain your Compose/Portainer stack separately for disaster recovery. No YAML needs to be pasted here.
